# Data

Cap: 500 words. The data layer and the rules around it.

## Files

| File | What |
| --- | --- |
| `src/lib/db/client.ts` | The Neon handle. Built on first use, so builds and tests run without a URL. The first query without one fails with a message that says what to do. |
| `src/lib/db/auth-schema.ts` | Generated by the Better Auth CLI, then passed through `scripts/fix-auth-schema.mjs` so every timestamp is `timestamptz`. Never edited by hand. |
| `src/lib/db/schema.ts` | Everything else. Re-exports the auth schema. |
| `src/lib/db/tables.ts` | Every table classified as tenant or shared. A test fails when one is missing. |
| `src/lib/db/scoped.ts` | `forOrganisation(id)`. The only way application code touches a tenant table. |
| `drizzle.config.ts` | Points drizzle-kit at both schema files and reads `.env.local`. |

## Adding a table

1. Write it in `schema.ts` with `organisation_id` not null, a foreign key to `organization` with cascade, and an index that starts with it. Every timestamp is `timestamp("x", { withTimezone: true })`.
2. Add it to `tenantTables` in `tables.ts`. If it truly holds no tenant data, `sharedTables`, with a line on why.
3. Add a block to `forOrganisation()` in `scoped.ts` with the queries the product needs. Every query includes the scope.
4. Run `pnpm test`. The tenancy test and the scoped test have to pass.
5. Push or migrate, below.

## Changing the auth tables

Change the config in `src/lib/auth/server.ts`, then `pnpm auth:generate`.
It needs Node 22 or later. Then push or migrate.

## Schema changes, by environment

Local and previews run `pnpm db:push` against their own Neon branch. It
diffs the schema and applies it. Fast and fine for data nobody keeps.

Production uses migrations. `pnpm db:generate` writes SQL under `drizzle/`,
which is committed. `pnpm db:migrate` with `DATABASE_URL` pointing at the
production branch applies it. The migration lands before the code that
needs it: one PR that adds columns and migrates, then the PR that uses
them. A destructive change is a third PR, after the old code is gone.

## Neon

One project per product. `main` is production. `dev` is local. A preview
that needs its own data gets a branch from `main`, and setup names them
after the slug. Branches are cheap. Deleting one is an ask-first action in
every skill.

## Identifiers and time

Ids are text UUIDs generated in the application. Every timestamp is
`timestamptz` in UTC, and the organisation row's `timezone` decides how it
renders. `src/lib/time/` is the only place that does date arithmetic.

## The scoped test

`tests/unit/scoped.test.ts` runs the real schema in PGlite, an in-process
Postgres, and proves that two organisations cannot see, change or delete
each other's rows. It runs in CI with no database. Extend it when a table
is added.
